## 3. The explicit question: clean read-only intelligence service versus rehabilitating the previous NEO runtime

**Answer: a clean, read-only intelligence service is preferable. Rehabilitating the previous runtime is not recommended.**

Cost comparison for the MVP scope (read-only review report of one strategy from CER evidence and fires, no order path), same unit and basis:

| Option | Scope | Cost | Residual debt / risk |
|---|---|---|---|
| Reuse the runtime as is | not possible: execution-capable code is in-process; import needs live infrastructure | n/a | violates the read-only rule |
| Rehabilitate the previous runtime | sever execution-capable code from a 3.6k-line observer; make 6 test files hermetic; manifest + CI; replace direct data reads by adapters; fence LLM stages; add CER client; add report | **40-70 ed** | a large code base with three monoliths and execution code to keep out; runtime state unknown; high regression risk without run-loop tests |
| Clean read-only service | small package: CER read client (CER's existing producer client reused), report builder (identity, evidence by class, promotion history, health, fires), an architecture test that forbids execution-capable imports, extract N-8 and N-9 as libraries | **20-30 ed** for the MVP report (plus 8-14 ed for N-8 and N-9 extraction); full parity with the learning pipeline later, +30-50 ed, deferred | small, testable, read-only by construction |

Evidence behind the answer: (1) the observer is not read-only (AUDIT-F 3.6, private index); (2) the only parts with proven offline tests (N-8, N-9, ledger writer, regime audit) are separable pure modules; (3) the parts that carry the risk (observer run loop, executor) have no run-loop tests and cannot be collected offline; (4) the observer failure class is UNVERIFIED, so rehabilitation would start from an unknown state; (5) NEO has no CER client or contract usage, so integration cost is paid in either option. Cost ranges are planning estimates; by these ranges clean is roughly 30-75 percent of the rehabilitation cost, and the risk difference matters more than the figures.

**Algorithms, tested logic, contracts and research findings worth retaining either way:** the judgement scorer and its tests (N-8); the strategy-health envelope validation and caveat rules and tests (N-9); the deterministic conflict scoring tables (N-10, needs tests); the ledger invariants (N-12); the pattern-maturity lifecycle and drift definitions (N-11); the regime / setup / retrace detection logic as documented algorithms; the runbook's data-flow description. **Not retained:** the order executor and related daemons (reference only for TRON hard-risk design), the LLM-driven narrative stages for the MVP, the chat-posting features.
