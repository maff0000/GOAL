## 3. The explicit question: clean read-only intelligence service versus rehabilitating the previous NEO runtime

**Answer: a clean, read-only intelligence service is preferable. Rehabilitating the previous runtime is not recommended.**

Cost comparison for the MVP scope (read-only review report of one strategy from CER evidence and fires, no order path), same unit and basis:

| Option | Scope | Cost | Residual debt / risk |
|---|---|---|---|
| Reuse the runtime as is | not possible: the observer is not read-only and needs live infrastructure | n/a | violates the read-only rule |
| Rehabilitate the previous runtime | sever order-capable code from the observer; make the affected tests hermetic; manifest + CI; replace direct data reads by adapters; fence LLM stages; add CER client; add report | **40-70 ed** | a large code base with order-capable code to keep out; runtime state unknown; high regression risk without run-loop tests |
| Clean read-only service | small package: CER read client (CER's existing producer client reused), report builder (identity, evidence by class, promotion history, health, fires), an architecture test that forbids execution-capable imports, extract the scorer and strategy-health consumer as libraries | **20-30 ed** for the MVP report (plus 8-14 ed for that extraction); full parity with the learning pipeline later, +30-50 ed, deferred | small, testable, read-only by construction |

Evidence behind the answer: (1) the observer is not approved as read-only (AUDIT-F 3.6, confidential record); (2) the parts with proven offline tests (scorer, strategy-health consumer, ledger writer and similar) are separable pure modules; (3) the parts that carry the risk (run loop, order-capable tooling) have no run-loop tests and cannot be collected offline; (4) the observer failure class is UNVERIFIED, so rehabilitation would start from an unknown state; (5) NEO has no CER client or contract usage, so integration cost is paid in either option. Cost ranges are planning estimates; by these ranges clean is roughly 30-75 percent of the rehabilitation cost, and the risk difference matters more than the figures.

**Retained either way (function level):** the tested scoring and strategy-health validation logic, deterministic conflict scoring (tests needed), the ledger invariants, and the documented analytical algorithms and lifecycle concepts, as designs to port. **Not retained:** the order-capable tooling (reference only for TRON hard-risk design), the LLM-driven stages for the MVP and the chat-oriented features.
